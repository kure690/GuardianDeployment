PROJECT OVERVIEW
================================================================================

GuardianPH V3 is an Emergency Dispatch Operator web application built with 
React and TypeScript. It's designed to manage emergency incidents, coordinate 
responders, and facilitate real-time communication between dispatchers, 
operation centers, and volunteers.

The system handles multiple types of emergency incidents:
- Medical emergencies
- Fire incidents
- Police/Crime incidents
- General emergencies

Key User Types:
1. Dispatchers - Handle incoming emergency calls and coordinate responses
2. Operation Centers (OpCen) - Manage multiple dispatchers and incidents
3. Volunteers - Report emergencies through mobile apps
4. Responders - Field personnel (ambulance, firetruck, police) responding to incidents

CORE FUNCTIONALITY BREAKDOWN
================================================================================

1. AUTHENTICATION & AUTHORIZATION
================================================================================

Login Flow (Login.tsx):
- Supports two user types: 'opcen' and 'dispatcher'
- Attempts login for both types simultaneously
- Stores authentication token and user data in localStorage
- Initializes Stream Chat client on successful login
- Redirects based on user type:
  * OpCen → /lgu-console
  * Guardian Dispatcher → /status
  * LGU Dispatcher → /lgu-main

Authentication State (App.tsx):
- Checks localStorage for existing session on mount
- Reconnects Stream Chat client if token exists
- Provides Socket.IO connection with authentication token
- Wraps app in QueryClientProvider for React Query

Socket Authentication (SocketProvider.tsx):
- Creates Socket.IO connection with token in auth payload
- Handles connection/disconnection states
- Shows loading screen while connecting
- Auto-reconnects on disconnect

================================================================================

2. DISPATCHER WORKFLOW
================================================================================

Status Page (Status.tsx):
- Dispatcher's main standby interface
- Toggle online/offline status (invisible mode in Stream Chat)
- Polls for new unaccepted incidents every 3 seconds
- Shows IncidentModal when new incident arrives
- Plays sound alert based on incident type
- Displays user profile with edit capability
- Accepts incident → navigates to MainScreen

Main Screen (MainScreen.tsx):
- Primary incident management interface
- Displays:
  * Incident details (type, ID, address)
  * Volunteer information (name, phone, profile)
  * Real-time chat with volunteer
  * Message templates sidebar
  * Incident verification toggle
  * Elapsed time since acceptance
- Features:
  * Connect to Operation Center
  * Open map view in new window
  * Initiate video call with volunteer
  * Send pre-defined message templates
  * Verify/close incidents
  * Receive responder status updates (on-scene, finished)

Incident Acceptance Flow:
1. Status page receives incident via polling
2. IncidentModal displays with incident details
3. Dispatcher clicks "ACCEPT"
4. Incident marked as accepted in database
5. Stream Chat channel created for communication
6. Initial message sent to volunteer
7. Navigate to MainScreen with incident ID

================================================================================

3. REAL-TIME COMMUNICATION
================================================================================

Socket.IO Integration:
- Global socket connection via SocketProvider
- Authenticated with JWT token
- Events handled:
  * requestOpCenConnect - Request connection to OpCen
  * opCenConnecting - OpCen is connecting
  * opCenConnected - OpCen connected successfully
  * opCenDeclined - OpCen declined connection
  * onlineUsersUpdate - List of online users
  * responderStatusUpdate - Responder location/status updates

Stream Chat:
- Used for text messaging between dispatchers and volunteers
- Channel naming: `{incidentType}-{incidentId.substring(5,9)}`
- Features:
  * Real-time messaging
  * Message reactions
  * Message editing/deletion
  * User presence (online/offline)
  * Profile image updates

Stream Video:
- Video calling between dispatchers and volunteers
- Call creation in Calls.tsx (popup window)
- Call handling in MainScreen.tsx (incoming calls)
- Features:
  * Ringing state
  * Join/leave controls
  * Audio/video toggle
  * Speaker layout
  * Call recording (via Stream)

Location Data Format:
- GeoJSON Point: { type: 'Point', coordinates: [longitude, latitude] }
- Note: GeoJSON uses [lon, lat] order (opposite of typical lat/lng)

5. INCIDENT MANAGEMENT
================================================================================

Incident Data Structure:
- _id: Unique incident identifier
- incidentType: 'Medical' | 'Fire' | 'Police' | 'General'
- isVerified: Boolean (dispatcher verification)
- isResolved: Boolean (incident closed)
- isAccepted: Boolean (assigned to dispatcher)
- user: Volunteer who reported
- incidentDetails:
  * coordinates: GeoJSON Point
  * incident: Incident description
  * incidentDescription: Detailed description
- responderCoordinates: Current responder location
- acceptedAt: Timestamp when accepted
- channelId: Stream Chat channel ID

Incident Lifecycle:
1. Created: Volunteer reports via mobile app
2. Pending: Available for dispatcher acceptance
3. Accepted: Assigned to dispatcher, channel created
4. Verified: Dispatcher verifies incident
5. In Progress: Responder en route or on scene
6. Resolved: Incident closed

useIncidentData Hook:
- Fetches incident data from API
- Manages incident state (verified, resolved, etc.)
- Fetches volunteer data
- Converts coordinates to address
- Updates in real-time

10. DATA FLOW
================================================================================

Incident Flow:
1. Volunteer reports via mobile app
2. Backend creates incident record
3. Dispatcher polls /incidents/for-dispatcher
4. IncidentModal shows new incident
5. Dispatcher accepts → updates incident
6. Stream Chat channel created
7. Real-time updates via Socket.IO
8. Responder assigned → location tracked
9. Incident resolved → closed

Real-time Updates:
- Socket.IO for instant notifications
- Polling for data consistency (every 3-5 seconds)
- React Query for cache management
- Stream SDK for chat/video events

State Management:
- Local state: useState for component-specific data
- Global state: React Query for server state
- Context: Socket.IO context for real-time
- localStorage: Authentication and user data
